# Botanic RS · демонстрационная версия

Самостоятельное приложение на PyQt6 для настоящей установки: две Daheng-камеры,
поворотная платформа X и вертикальная ось Z с VCP-контроллером.
Главный экран содержит две кнопки: **Старт** и **Стоп**.

## Запуск

Из каталога `demo_botanic_rs`:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python app.py
```

В существующее `.venv` зависимости уже установлены. Для работы камер необходим
системный **Daheng Galaxy SDK** (библиотека `libgxiapi` на Linux). Python-обёртка
`iai-gxipy` устанавливается из `requirements.txt`. Подключённые устройства должны
быть доступны текущему пользователю; камеры и serial-порт открывает один экземпляр приложения.

При необходимости порт можно указать явно:

```bash
VCP_PORT=/dev/ttyACM0 .venv/bin/python app.py
```

Без указания порта приложение ищет контроллер и проверяет ответ `POS`.
Повторные попытки подключения выполняются автоматически. «Старт» доступен после
подключения контроллера и получения кадров **обеих** камер.

Для просмотра отчёта без обращения к оборудованию:

```bash
.venv/bin/python app.py --report-only
```

`--windowed` открывает обычное окно вместо полноэкранного. Приложение можно
запускать из другого рабочего каталога: конфигурация и фотографии привязаны
к расположению `app.py`.

## Сценарий

1. **Старт**: `HOME` и ожидание нижней позиции Z = 0, затем установка лимита Z,
   скоростей и белой подсветки.
2. Относительный поворот платформы **+45°**. Завершение движения определяется
   по повторным показаниям `POS`, затем выдерживается пауза 0,7 с.
3. Получение свежих кадров левой и правой камер, сохранение стереопары.
4. Подъём камер на **300 мм**, ожидание достигнутой позиции, следующий поворот.
5. Съёмка производится на Z = **0, 300, 600, 900 и 1200 мм**. Последний подъём
   ограничен **1355 мм**; после него автоматически открывается отчёт.

Полный проход даёт **5 стереопар / 10 фотографий**. Камеры, как в исходной
установке, читаются последовательно. Приложение не предполагает аппаратно
синхронную экспозицию.

**Стоп** действует во время возврата HOME, поворота, паузы, съёмки и подъёма:
отменяет продолжение цикла, отправляет `STOP` и открывает отчёт.
Запоздалый кадр не запускает следующее движение и не дописывает завершённую сессию.
При ошибке оборудования цикл также останавливается, а причина показывается в отчёте.
Подсветка остаётся включённой после завершения, остановки и закрытия приложения.

Контроллер может выполнять команды настройки, движения и света без текстового
подтверждения. Пустой ответ на `SMLZ_1355` и подобные команды допускается;
явные `ERR` обрабатываются, а достижение позиции подтверждается координатами `POS`.
Отсутствие ответа на сам `POS` остаётся ошибкой связи. Ошибка съёмки не переоткрывает
serial-порт; переподключение выполняется после трёх подряд неудачных опросов позиции.

**Закрыть** возвращает к камерам. Следующий **Старт** снова начинает проход снизу.
Координата X сохраняется между сеансами: повороты всегда относительные +45°.

Выход — `Alt+F4` либо `Esc` на главном экране в ожидании. Во время съёмки `Esc`
работает как «Стоп», в отчёте — как «Закрыть». Закрытие приложения сначала
останавливает установку и завершает аппаратные потоки.

## Демонстрационный отчёт

Полноэкранный отчёт содержит вымышленные показатели морфологии и продуктивности,
а также процедурное цветное **XYZ-облако гороха без горшка**: стебель, листочки,
прилистники, усики, бобы и цветки. Модель и основные морфологические показатели
воспроизводимы; количество органов согласовано с генератором.

Облако плавно вращается; мышь меняет ракурс, колесо — масштаб, двойной щелчок
сбрасывает вид. Программный просмотрщик работает без OpenGL и Open3D.
В блоке «Сеанс съёмки» отображаются фактические число сохранённых кадров,
длительность, достигнутая высота и причина завершения.

## Настройки

Основные значения в `config.json`:

| Параметр | Значение |
|---|---|
| `port`, `baud` | Автопоиск, 115200 |
| `rotation_deg` | 45° |
| `z_step_mm`, `z_max_mm` | 300 / 1355 мм |
| `x_speed`, `z_speed` | 45°/с, 40 мм/с |
| `x_acceleration` | 13°/с² |
| `settle_s` | 0,7 с после поворота |
| `left_sn`, `right_sn` | GCA25140001 / GCA25140002 |
| `left_index`, `right_index` | Резервные индексы 0 / 1 |
| `camera_width`, `camera_height` | 4096 × 3000 |
| `exposure_us` | 30000 мкс |
| `white_light` | 100% |
| `swap_red_blue` | `true`, преобразование цвета как в текущей установке |

Поддерживаются переопределения окружением: `VCP_PORT`, `DAHENG_LEFT_SN`,
`DAHENG_RIGHT_SN`, `DAHENG_LEFT_INDEX`, `DAHENG_RIGHT_INDEX`,
`DAHENG_EXPOSURE_TIME`.

Ориентация кадров соответствует установке: левый поворачивается на 90° по часовой
стрелке, правый — против. Экспозиция, усиление и баланс белого заданы по рабочему
пресету NP-1230UC. Используются исходные кадры без rectification.

## Фотографии

```text
captures/<дата_время>/
  session.json
  left/left_x45.0_z0.0_photo_001.png
  right/right_x45.0_z0.0_photo_001.png
  ...
```

В `session.json` записаны реальные координаты, пути стереопар, время и состояние
сессии (`running`, `completed`, `stopped`, `error`). Обе стороны пары фиксируются
вместе; ошибки кодирования/записи не считаются успешной съёмкой.

## Проверки

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Проверки используют подставные камеры и контроллер, запускают цикл и потоки,
проверяют остановку на разных этапах, верхний предел, сохранение PNG,
запоздалые кадры, ошибки связи, повторный запуск и закрытие окна. GUI проверяется
через Qt offscreen с настоящим VCP-клиентом и эмулятором serial, отвечающим только
на `POS`. Временные данные и снимки экранов находятся в `.checks/`.

## Модули

- `core/scan.py` — последовательность движения и съёмки, отмена и таймауты.
- `hardware/controller.py` — serial-протокол и поиск контроллера.
- `hardware/cameras.py`, `hardware/workers.py` — SDK Daheng и аппаратные потоки.
- `core/session.py` — сохранение стереопар и метаданных.
- `core/pea_cloud.py` — синтетическая модель гороха.
- `ui/` — камеры, тёмная тема, отчёт и интерактивный просмотр XYZ.

Все исходники, настройки и данные демонстрации находятся в `demo_botanic_rs`.
